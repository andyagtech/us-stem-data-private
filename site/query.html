What this is

Every table below is loaded into your browser and queried there. Nothing is sent to a server. The data is the same data the rest of the site is built from.

Start with an example

The grey buttons under the Run box are worked examples for whichever table you have selected. They are the quickest way in: click one, read the SQL, then change it.

Pick a table in the left rail to see its own examples.

The tables

stem_records
509,072 STEM theses and dissertations. One row per award: university, department, year, author, title. All of them load: a COUNT(*) here returns 509,072.
nonstem_records
199,321 of the same, outside STEM.
h1b_perm_public
42,833 certified green-card filings by universities, school districts, state agencies and utilities. The only table with citizenship and country of birth.
h1b_industry
4,783 six-digit NAICS industries, with filings, employers and median wage.
h1b_occupation
1,043 SOC occupations, the same way.
h1b_employers
38,836 employers with their filing counts and wage levels.

Reference tables

These exist so the others can be joined. Each one is built by a script in this repository and the data methodology describes how — what was normalised, what was merged, and what was deliberately left apart.

field_by_institution
12,594 rows, pre-summed, with the field name spelled out. Non-resident share of doctorates for one field at one university, over 2015–2022 on a single award basis, with the institution name already joined in. Start here. The same question against ipeds_awards takes about two seconds; this answers in under a tenth.
field_trend
231 fields, each with its non-resident share in 2011–2016 and again in 2017–2022 and the change between them. Both windows sit after the 2010 recode, so the comparison is like for like. Fields under 200 awards in either window are left out: a small denominator turns noise into a trend.
ipeds_awards
260,170 rows: year, institution, field code, award basis, awards, non-residents. Every share published on this site is computed from this table, so any of them can be recomputed here. Use it when you need a different window, a different basis, or a year-by-year series. The year column is award_year, not year, because the SQL engine treats YEAR as a keyword and a.year fails to parse inside a join. Never sum across basis: IPEDS recoded award levels in 2010 and the transition years appear under both, so adding them counts those years twice.
institutions
2,290 institutions with their IPEDS identifier, state, control and enrolment. The join key for everything above.
field_shares
268 ranked institution–field pairs: the six critical sectors and the wider STEM search list. The restriction column is null for the STEM list, which means no claim is made, not that no regime applies.
department_pages
The department pages resolved and verified for those fields, and which roster each publishes. Every URL was fetched and checked, including for pages that answer 200 with a “not found” body.
cap_exempt
2,403 cap-exempt employers.

Joining them

h1b_employers.naics joins to h1b_industry.naics. h1b_perm_public.employer joins to h1b_employers.employer once both sides are upper-cased. university is the same key in both record tables.

ipeds_awards.unitid joins to institutions.unitid, and field_shares.institution to department_pages.institution. Prefer field_by_institution where it will do: it has the institution name in it already, so the commonest question needs no join at all.

The examples marked join show each of these.

Reading the numbers honestly

  • A filing is permission to employ, not proof of hiring. Every count is a ceiling on intent.
  • Count filings by application. One application can cover many positions, and weighting by positions hands every share to the bulk filers.
  • Record counts differ by how much a university publishes, not only by how much it awards.
